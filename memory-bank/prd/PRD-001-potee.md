# PRD-001: Potee — визуальный планировщик проектов

## Problem

Человек, который ведёт одновременно несколько проектов (рабочих, личных,
семейных), держит их сроки и ближайшие шаги в голове, в календаре или в
таск-трекере. Календарь показывает дни, но не показывает проекты целиком;
трекер показывает задачи, но не показывает время. Ответ на вопросы «что
сейчас идёт параллельно», «что заканчивается на этой неделе» и «какой
следующий шаг в каждом проекте» приходится собирать вручную.

Существующие диаграммы Ганта решают это для команд, но тяжелы для одного
человека: регистрация, настройка, формы, зависимости, роли. Порог входа выше,
чем ценность для личного планирования.

Potee (2012, перезапуск 2026-10-01 на potee.pismenny.ru) отвечает на эти
вопросы одним экраном: проекты — полосы на ленте времени, вехи — события на
них, всё правится прямым манипулированием и работает без регистрации.
Общий контекст продукта — в [`../product/context.md`](../product/context.md).

## Users And Jobs

| User / Segment | Job To Be Done | Current Pain |
| --- | --- | --- |
| `solo-planner` — человек с 3–10 параллельными проектами (фрилансер, предприниматель, руководитель) | Видеть все свои проекты во времени и следующий шаг в каждом | Календарь и трекер не дают картины «проекты × время»; Гант-сервисы тяжелы для одного |
| `household` — семья или пара, планирующая общие дела (ремонт, отпуск, переезд) | Договориться о сроках и вехах и видеть одно и то же | Сроки живут в переписке; нет общей наглядной картинки |
| `collaborator` — получатель ссылки на проект | Быстро увидеть и при необходимости поправить общий проект | Чтобы посмотреть чужой план, обычно надо регистрироваться и разбираться в интерфейсе |
| `curious-visitor` — человек, пришедший с pismenny.ru или по ссылке | За минуту понять, подходит ли инструмент | Большинство планировщиков требуют регистрацию до первого результата |

## Goals

- `G-01` Новый посетитель за первую минуту видит ценность: живая доска с
  примерами без регистрации и создание своего проекта в одно действие.
- `G-02` Картина «все проекты × время» доступна одним действием (клик по
  логотипу) и читается без пояснений: сегодня, сроки, ближайшие вехи.
- `G-03` Планирование без форм: создание, сроки, порядок, вехи и их перенос —
  прямым манипулированием на ленте, с отменой ошибочного удаления.
- `G-04` Доска не теряется: регистрация по email сохраняет уже созданную
  анонимную доску, вход на другом устройстве объединяет сделанное.
- `G-05` Совместная работа без регистрации получателя: ссылка на проект
  добавляет его на доску получателя, изменения видны обоим.
- `G-06` (желательно) Русский интерфейс по умолчанию и удобная работа с
  телефона.

## Non-Goals

- `NG-01` Управление задачами внутри проекта (чек-листы, исполнители,
  статусы) — Potee про время и вехи, а не про таск-трекинг.
- `NG-02` Зависимости между проектами, критический путь, ресурсное
  планирование — это корпоративный Гант, не наш сегмент.
- `NG-03` Роли и права внутри проекта: сейчас любой участник по ссылке может
  править общие данные проекта; разграничение не вводим без отдельного решения.
- `NG-04` Платные тарифы и монетизация в рамках этой инициативы.
- `NG-05` Нативные мобильные приложения; телефон — через адаптивный веб.

## Product Scope

### In Scope

- Анонимная доска с демо-примерами при первом визите (`UC-001`).
- Лента времени с масштабами «дни / недели / месяцы», плавным зумом,
  панорамированием, переходом к сегодня и обзором «все проекты на экране»
  (`UC-002`).
- Проекты: создание (кнопка, Enter, двойной клик), сроки растягиванием краёв,
  порядок перетаскиванием, название, цвет, «Целиком», удаление с отменой
  (`UC-003`–`UC-006`).
- События: добавление двойным кликом, перенос, переименование, удаление с
  отменой; подписи без наложений (ярусы) (`UC-007`, `UC-008`).
- Совместная работа по ссылке (`UC-009`, `UC-010`).
- Аккаунт по email и паролю: регистрация с сохранением доски, вход со
  слиянием, выход, восстановление пароля письмом (`UC-011`–`UC-014`).
- Административный раздел для просмотра и исправления данных (`UC-015`).
- Русский и английский интерфейс (по языку браузера, русский по умолчанию),
  подсказка по жестам, адаптивная шапка и панель проекта на телефоне.
- Карточка продукта на pismenny.ru/products как основной канал привлечения.

### Out Of Scope

- Вход через OAuth (Google, Яндекс, Telegram) — отложен решением 2026-10-01.
- Автоматическая очистка заброшенных анонимных досок по расписанию — задача
  есть, запуск по расписанию не включаем (решение 2026-10-01).
- Уведомления и напоминания о вехах (email, Telegram).
- Импорт/экспорт (iCal, CSV), интеграции с календарями.
- Продуктовая аналитика третьих сторон.

## UX / Business Rules

- `BR-01` Ценность до регистрации: лендинг и страницы входа не создают
  пользователя; первый заход на доску создаёт анонимную доску с примерами.
- `BR-02` Прямое манипулирование вместо форм: всё, что можно сделать на
  ленте, делается на ленте; формы — только для текста (название проекта или
  события) и аккаунта.
- `BR-03` Проект общий для участников, строка доски — личная: название, сроки
  и события видят все участники; цвет и порядок — свои у каждого.
- `BR-04` Удаление строки владельцем удаляет проект для всех; участник по
  ссылке удаляет проект только со своей доски.
- `BR-05` Любое удаление можно отменить в течение 5 секунд; подтверждающих
  диалогов браузера нет.
- `BR-06` События всегда внутри сроков проекта; сроки нельзя сжать так, чтобы
  событие оказалось снаружи.
- `BR-07` Регистрация не теряет данные: анонимная доска становится доской
  аккаунта; при входе переносится всё, что посетитель создал или изменил, а
  нетронутые примеры не дублируются.
- `BR-08` Ошибки входа и восстановления пароля не раскрывают, зарегистрирован
  ли email.
- `BR-09` Вид доски (масштаб, дата в центре, прокрутка) сохраняется и
  восстанавливается при следующем визите.
- `BR-10` Язык интерфейса и примеров — русский по умолчанию, английский для
  браузеров с английским в приоритете.

## Success Metrics

Аналитика в продукте пока не подключена; метрики считаются запросами к базе
приложения (`users`, `projects`, `events`, `project_connections`,
`dashboards`). Базовые значения появятся после первых 4 недель после
перезапуска 2026-10-01.

| Metric ID | Metric | Baseline | Target | Measurement method |
| --- | --- | --- | --- | --- |
| `MET-01` | Активация: доля новых досок, где посетитель сделал хотя бы одно своё действие (создал/изменил проект или событие) | нет данных | ≥ 40 % | Доля пользователей за неделю, у которых есть проект с `demo = false` |
| `MET-02` | Возврат D7: доля активированных посетителей, вернувшихся через 7+ дней | нет данных | ≥ 20 % | `last_seen_at` ≥ `created_at` + 7 дней среди активированных |
| `MET-03` | Сохранение доски: доля активированных, зарегистрировавшихся по email | нет данных | ≥ 10 % | Доля пользователей с `email` среди активированных за месяц |
| `MET-04` | Глубина использования: медиана проектов и событий на активную доску | нет данных | ≥ 3 проекта, ≥ 4 события | Медианы по пользователям, заходившим за последние 30 дней |
| `MET-05` | Совместная работа: доля активных досок с проектом, полученным по ссылке | нет данных | ≥ 10 % | Пользователи с `project_connections`, где они не владельцы проекта |
| `MET-06` | Надёжность: доля изменений, откатанных из-за ошибки сохранения | нет данных | < 0,5 % | Логи приложения: ответы API 4xx/5xx на изменяющие запросы к общему числу |

## Risks And Open Questions

- `RISK-01` Инфраструктура: общий PostgreSQL офиса и канал до него давали
  сбои 2026-10-01 (таймауты, DNS); Potee целиком зависит от этой базы.
- `RISK-02` Ссылка на проект даёт право редактировать общие данные любому, у
  кого она есть; утечка ссылки = чужие правки (`NG-03`).
- `RISK-03` Анонимные доски копятся без автоматической очистки; рост таблиц
  при трафике с ботов.
- `RISK-04` Письма восстановления уходят с личного ящика
  `danil@brandymint.ru`: лимиты отправки и смешение с личной перепиской.
- `RISK-05` Обнаруживаемость жестов: ценность держится на прямом
  манипулировании, которое новичок может не найти (частично закрыто
  подсказкой «?», пустым состоянием и ручками).
- `OQ-01` Какой канал привлечения кроме pismenny.ru (статья, клуб «Агенты в
  деле», Telegram) и как отличать его трафик без внешней аналитики?
- `OQ-02` Нужны ли права в общих проектах (только просмотр / правка) и как
  отзывать ссылку?
- `OQ-03` Когда возвращаться к OAuth (Google, Яндекс, Telegram) — после
  какого значения `MET-03`?
- `OQ-04` Нужны ли напоминания о вехах — это главный кандидат на рост `MET-02`.
- `OQ-05` Отдельный адрес отправителя для писем (`no-reply@pismenny.ru`)
  вместо личного ящика.
